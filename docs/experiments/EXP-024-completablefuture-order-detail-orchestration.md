# EXP-024：CompletableFuture 异步编排的整体超时与部分降级

## 1. 实验目标

模拟订单详情接口，同时调用订单、商品、库存三个下游服务，验证：

- 多个下游任务并行执行与结果组合。
- 商品服务失败时进行部分降级。
- 库存服务超时时整体失败。
- 整体响应超时时返回超时异常。
- 订单核心服务失败时不允许降级。
- 超时后观察底层任务是否仍然运行。

## 2. 实验场景

| 场景 | 订单服务 | 商品服务 | 库存服务 | 预期 |
|---|---|---|---|---|
| A 正常 | 成功 | 成功 | 成功 | 返回完整详情 |
| B 商品降级 | 成功 | 失败 | 成功 | 商品使用默认信息 |
| C 库存超时 | 成功 | 成功 | 超时 | 整体失败 |
| D 整体超时 | 阻塞 | 成功 | 成功 | 整体超时 |
| E 订单失败 | 失败 | 成功 | 成功 | 整体失败 |

## 3. 实验参数

- 整体超时：800ms（正常及商品降级场景）
- 库存依赖超时：150ms
- 整体超时实验：150ms
- 使用独立 Executor 隔离订单、商品和库存任务
- 使用 CountDownLatch 控制任务执行时机

## 4. 实验结果

测试结果：5 个测试全部通过，0 失败，0 错误。

### A：正常组合

实际结果：

ORDER-1001 | PRODUCT-2001 | INVENTORY-3001

结论：多个下游任务可以并行执行，使用 thenCombine 组合结果。

### B：商品服务失败并降级

实际结果：

ORDER-1002 | PRODUCT-DEFAULT | INVENTORY-3002

商品服务异常被 exceptionally 转换为默认商品信息，整体组合成功。

结论：适合降级的展示型数据可以设置明确的默认值，但必须由业务定义降级边界。

### C：库存服务超时

实际结果：

- detail Future 以 TimeoutException 异常完成。
- 放行 CountDownLatch 前，库存任务尚未结束。
- 放行后，库存任务最终结束。

结论：依赖 Future 超时完成，不代表底层执行任务已经停止。

### D：整体响应超时

实际结果：

- detail Future 以 TimeoutException 异常完成。
- 放行 CountDownLatch 前，订单任务尚未结束。
- 放行后，订单任务最终结束。

结论：整体超时可以限制调用方等待时间，但不会自动终止正在执行的下游任务。

### E：订单核心服务失败

实际结果：

IllegalStateException: Order service unavailable

结论：订单核心依赖失败向上传播，不能被商品信息的降级逻辑掩盖。

## 5. 核心技术结论

1. thenCombine 可以组合两个阶段的结果，适合并行下游调用。
2. exceptionally 可以恢复异常，但应仅用于业务允许降级的依赖。
3. orTimeout 会使 CompletableFuture 在超时后异常完成。
4. orTimeout 不保证中断底层 Supplier，也不保证释放其占用的资源。
5. 单个依赖超时和整体响应超时需要分别设计。
6. Future 已经超时，不代表底层 HTTP、数据库或其他调用已经停止。

## 6. 生产环境风险

如果只设置 CompletableFuture 超时，而没有为底层调用设置超时和取消机制，可能发生：

- API 已返回超时，但下游调用仍在执行。
- 工作线程持续被慢任务占用。
- HTTP 连接池或数据库连接池资源迟迟不能释放。
- 大量超时请求积累后，进一步造成线程池耗尽。

生产环境还需要结合 HTTP 客户端连接/响应超时、数据库查询超时、线程池隔离、取消传播和资源清理机制。

## 7. 实验局限

本实验验证了 Future 层面的超时与异常传播，没有验证：

- HTTP 客户端和数据库驱动是否真正响应取消。
- 超时后底层任务能否可靠停止。
- 从整体 Deadline 计算并向下游传递剩余时间。
- 线程池、连接池在持续超时压力下的资源变化。

因此，本实验不能证明生产环境中的超时任务一定能够被终止。

## 8. 验收结果

- [x] 三个下游正常组合
- [x] 商品服务异常降级
- [x] 库存依赖超时导致整体失败
- [x] 整体超时导致响应失败
- [x] 订单核心服务失败不降级
- [x] 验证超时后底层任务仍可能继续执行
- [x] 测试线程池正常关闭

## 9. 最终结论

CompletableFuture 能够解决异步任务编排、结果组合和异常恢复问题，但 Future 层面的超时不等于底层任务的资源释放。

生产级异步编排必须同时设计业务降级边界、依赖超时、整体 Deadline、取消传播和资源回收机制。
