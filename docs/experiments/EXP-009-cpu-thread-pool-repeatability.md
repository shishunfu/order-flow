# EXP-009：CPU 线程池重复性与稳定性实验

## 1. 实验目的

通过重复测试不同 Worker 数量下 CPU 密集型任务的吞吐量，验证 EXP-008 中观察到的线程数收益拐点是否稳定。

## 2. 实验环境

- JVM 可用处理器数：16
- 任务数量：200
- 单任务计算次数：5,000,000
- 预热任务数：20
- 每组重复次数：5
- Worker 数：4、8、16、32
- 队列容量：200
- 拒绝策略：AbortPolicy

## 3. 实验结果

| Worker | 吞吐量中位数 | 最小值 | 最大值 | Range |
|---:|---:|---:|---:|---:|
| 4 | 658.79 | 652.87 | 663.91 | 11.03 |
| 8 | 1180.86 | 1132.80 | 1185.87 | 53.07 |
| 16 | 1643.86 | 1509.84 | 1793.91 | 284.07 |
| 32 | 1804.15 | 1746.81 | 1807.97 | 61.16 |

单位：tasks/s。

## 4. 关键发现

1. 4 → 8 Worker，吞吐量提升约 79.2%。
2. 8 → 16 Worker，吞吐量提升约 39.2%。
3. 16 → 32 Worker，吞吐量提升约 9.8%。
4. 16 Worker 组的结果波动最大，相对 Range 约 17.28%。
5. 32 Worker 组相对 Range 约 3.39%，本次重复测试结果相对稳定。

## 5. 实验结论

本次实验表明，增加 CPU 线程数仍然能够提高整体吞吐量，但收益逐步递减。

32 Worker 的吞吐量中位数高于 16 Worker，但这并不意味着 32 Worker 一定是更合适的生产配置。还需要考虑线程调度成本、CPU 资源占用、任务执行时间和系统整体响应能力。

本次实验修正了 EXP-008 中关于 16 Worker 已到达吞吐量拐点的初步判断。

## 6. 实验局限

- 每组只重复测试 5 次。
- 测试顺序固定，可能受到机器运行状态影响。
- 没有采集 CPU 利用率、CPU 频率和上下文切换指标。
- 预热发生在测试线程，而非每个 Worker 线程。
- 该实验不是严格的 JMH 微基准测试。

## 7. 后续改进

下一轮应增加重复次数、随机化线程数组测试顺序，并适当增加任务数量，进一步验证不同线程数下的吞吐量与稳定性。
